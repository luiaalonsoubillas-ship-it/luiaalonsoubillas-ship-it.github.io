Vigía, AI disclosure agent for public companies

Helps listed companies in Latin America decide what they must disclose to the regulator, and before the deadline
Built with a former regulator

The problem

A major contract, a lawsuit, a sanction: a listed company has a short legal window to decide if it must be disclosed. Get it wrong and the regulator fines them.

What it does

Analyzes the event against the regulation, recommends whether to disclose citing the exact articles, and drafts the filing. Legal, finance and IR work off one record, with a full audit trail.

The key design choice

The agent proposes, deterministic rules decide, a human signs. Materiality thresholds live in code, not in the prompt, so every call is auditable.

How it's evaluated

Tested against real cases labeled by a domain expert. A keyword baseline gets fewer than half right: this takes judgment, not search.

Contract Review Agent

Upload a contract and ask an agent about its risks and clauses. Built during an applied AI product program.
v1 → v2

Problem

Reviewing a contract for key terms and risks is slow, and generic chatbots answer without pointing to the source.

Version 1

A web app connected to an n8n agent. It extracts the full text of the PDF and sends all of it to the model with each question. Simple, but it slows down and loses focus on long contracts.

Version 2: agentic RAG

Contracts are split into chunks, embedded, and stored in a vector store. The agent uses that store as a tool, deciding when to search and answering from the relevant passages only.

How I build

What years of enterprise delivery taught me about getting AI into production.

1. Start from the decision

Name the one decision or task the system must improve, and who owns it, before choosing any model.

2. Feed it the right context

Knowledge (policies, playbooks, materials), memory (who's asking, what's happened), and tools. Scoped deliberately, never dumped in whole.

3. Ground every answer

Retrieve from real sources and cite them. If the system can't point to evidence, it shouldn't answer.

4. Evals before scale

Build an answer key with the experts first, measure the system against how the work is done today, then expand.

5. Humans at the checkpoints

Keep people where the cost of a mistake is high, and automate the rest.
